# 校园闲置物品交换系统 - 课程设计报告

## 一、需求分析

### 1.1 项目背景

随着高校学生人数的不断增加，校园内闲置物品的数量也随之增多。学生在毕业季、换宿舍、社团活动等场景中存在大量闲置物品和短期服务需求。传统的二手交易方式存在信息不对称、交易安全难以保障等问题。本系统旨在构建一个校园内循环交换平台，实现"以物换物、技能换物、信用评价、安全面交"的功能，减少浪费，提高闲置资源利用率。

### 1.2 应用场景

| 场景 | 描述 | 典型用户 |
| --- | --- | --- |
| 毕业季闲置处理 | 毕业生处理不再需要的物品 | 大四学生 |
| 宿舍搬迁 | 换宿舍时交换或获取生活用品 | 全体学生 |
| 社团活动 | 社团间共享物资或技能互助 | 社团成员 |
| 技能互助 | 学生之间互相传授技能 | 有特长的学生 |

### 1.3 功能需求

根据用户调研和需求分析，系统需要实现以下功能：

**用户模块**：
- 用户注册、登录、退出
- 个人资料管理
- 信用分系统

**物品模块**：
- 物品发布（含图片上传）
- 物品分类浏览
- 关键词搜索
- 物品详情查看

**交换模块**：
- 发起交换申请
- 交换状态管理（待确认、已同意、已完成、已拒绝）
- 面交时间地点协商

**消息模块**：
- 站内消息沟通
- 系统通知

**社交模块**：
- 物品收藏
- 智能推荐
- 信用评价

**管理模块**：
- 举报审核
- 运营数据看板

## 二、系统设计

### 2.1 架构设计

采用前后端分离架构：

```
┌─────────────────────────────────────────────────────────────┐
│                      前端层 (Vue 3)                         │
│  Home  |  ItemDetail  |  Publish  |  Exchanges  |  Admin   │
├─────────────────────────────────────────────────────────────┤
│                      API层 (RESTful)                        │
│  /api/users  |  /api/items  |  /api/exchanges  |  /api/admin│
├─────────────────────────────────────────────────────────────┤
│                      后端层 (Go + Gin)                      │
│  Handler  |  Service  |  Middleware  |  Model              │
├─────────────────────────────────────────────────────────────┤
│                    数据层 (MySQL/JSON)                      │
│  users  |  items  |  exchanges  |  messages  |  favorites  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 模块划分

| 模块 | 功能说明 | 对应文件 |
| --- | --- | --- |
| 用户认证 | 登录、注册、JWT验证 | server/handler/auth.go |
| 物品管理 | 物品CRUD、搜索筛选 | server/handler/item.go |
| 交换流程 | 交换申请、状态流转 | server/handler/exchange.go |
| 消息系统 | 消息收发、通知 | server/handler/message.go |
| 收藏推荐 | 收藏管理、推荐算法 | server/handler/misc.go |
| 评价系统 | 信用评价、评分 | server/handler/rating.go |
| 后台管理 | 举报审核、数据统计 | server/handler/admin.go |

## 七、代码安全性注意事项与解决方案

### 7.1 安全风险点

| 风险点 | 描述 | 严重程度 |
| --- | --- | --- |
| SQL注入 | 用户输入未经过滤直接拼接SQL | 高 |
| XSS攻击 | 用户提交的内容可能包含恶意脚本 | 高 |
| 文件上传漏洞 | 恶意文件上传 | 高 |
| JWT伪造 | Token被伪造或篡改 | 高 |
| 越权访问 | 用户访问他人数据 | 中 |
| 密码泄露 | 密码明文存储 | 高 |

### 7.2 解决方案

| 风险点 | 解决方案 |
| --- | --- |
| SQL注入 | 使用ORM框架或参数化查询 |
| XSS攻击 | 前端使用v-html时进行转义，后端对用户输入进行过滤 |
| 文件上传漏洞 | 限制文件类型、大小，存储时重命名文件 |
| JWT伪造 | 使用强密钥签名，设置合理的过期时间 |
| 越权访问 | 在每个API中验证用户权限，确保只能访问自己的数据 |
| 密码泄露 | 使用bcrypt或scrypt加密存储密码 |

## 八、总结

本系统通过前后端分离架构，实现了校园闲置物品交换的完整功能。系统涵盖用户认证、物品管理、交换流程、消息沟通、信用评价等核心模块，满足学生在校园内进行物品交换和技能互助的需求。通过信用分系统和举报审核机制，保障了交易的安全性和可靠性。
